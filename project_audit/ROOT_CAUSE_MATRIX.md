## Status vocabulary

- `PROVEN`: directly established by code/runtime/real video.
- `OPERATOR-GT`: human semantic ground truth supplied by the operator.
- `INFERRED`: strong causal hypothesis requiring a targeted trace/test.
- `OPEN`: not yet measured.
- `BLOCKED`: prerequisite missing.
- `READY-FOR-TDD`: acceptance test can be written before implementation.
- `CLOSED`: all unit, regression, real-video, frozen-suite, and reproducibility gates passed.

## Hard invariants preserved throughout

1. Existing true-litter positives must not be sacrificed silently.
2. Stable IDs are claims about physical continuity, never guesses.
3. No event is final until causal chronology and final semantic outcome are valid.
4. Uncertainty fails to `UNRESOLVED/REJECTED`, never to accusation.
5. Proposals/novelty do not independently become semantic waste.
6. Frozen actor/object ownership remains authoritative only while physical-continuity confidence remains valid.
7. Production inference reads an explicit immutable pin; no clip silently changes the next clip.
8. Every repair is test-first, one vertical behavior slice at a time.
9. No video-, filename-, timestamp-, actor-, color-, or object-ID-specific rule.
10. `CLOSED` requires unit + regression + real-video + frozen-suite + reproducibility evidence.

## Closure rule

A row may move to `CLOSED` only when `CHANGE_LEDGER.md` links:

- the failing test observed before implementation;
- the minimal code change;
- focused and full test results;
- named real-video before/after artifacts;
- frozen metrics and regression comparison;
- reproducibility result;
- checkpoint/rollback identifier;
- residual risk and explicit go/no-go decision.
